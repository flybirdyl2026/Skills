# 需求文档质量评分器

从测试工程师视角对需求文档进行系统化质量评估，输出量化评分和具体改进建议。评估达标后可联动测试用例生成。

## 评分维度（六维模型）

| 维度 | 权重 | 核心关注点 |
|------|------|------------|
| 可测试性 | 30% | 能否验证？验收标准是否明确？ |
| 完整性 | 25% | 是否覆盖边界、异常、前置条件？ |
| 清晰性 | 20% | 描述是否无歧义？术语是否统一？ |
| 一致性 | 10% | 需求间是否存在矛盾？ |
| 可追溯性 | 10% | 是否有唯一标识和来源追溯？ |
| 可实现性 | 5% | 技术上是否可行？ |

## 评分标准

每个维度按 1-5 分评估：

- **5分（优秀）**：完全满足标准，无需改进
- **4分（良好）**：基本满足，有小瑕疵
- **3分（一般）**：部分满足，有明显缺陷
- **2分（较差）**：严重不足，影响测试设计
- **1分（极差）**：几乎无法使用

## 执行流程

### 1. 文档解析

读取需求文档，识别以下要素：
- 功能需求条目
- 业务规则
- 数据约束
- 交互流程
- 非功能需求

### 2. 分维度评分

对每个维度逐项检查，详见 `references/scoring-criteria.md`。

### 3. 问题清单

列出所有发现的问题，按严重程度排序：
- 🔴 阻塞：无法进行测试设计
- 🟡 警告：影响测试覆盖率
- 🔵 建议：可优化项

### 4. 综合评分

```
总分 = Σ(维度分 × 权重)
```

### 5. 输出报告

运行 `scripts/generate_report.py` 生成 Word 格式评估报告，输出到 `analysis_report/` 目录。

### 6. 联动测试用例生成

评估完成后，根据评分等级决定下一步：

| 评分等级 | 建议动作 |
|----------|----------|
| A/B (>=75) | 直接联动 `generate-test-cases` skill 生成测试用例 |
| C (60-74) | 建议先修复警告问题，可同步生成测试用例 |
| D/E (<60) | 必须先补充P0阻塞问题，不建议生成测试用例 |

联动时将以下信息传递给 `generate-test-cases`：
1. 需求文档路径
2. 评估摘要（各维度得分 + 问题清单）
3. 重点关注项（评估中发现的边界条件、异常场景缺陷，作为测试用例补充提示）

联动命令：
```bash
python <generate-test-cases-path>/scripts/generate_cases.py \
  --requirements_file "<需求文档.docx>" \
  --output_file "<generate-test-cases-path>/output/{项目名}测试用例.xlsx"
```

项目名提取规则：去掉需求文档名中的"需求分析说明书"、"需求文档"、"需求规格说明书"等后缀。

## 评估等级

| 分数段 | 等级 | 说明 |
|--------|------|------|
| 90-100 | A（优秀） | 可直接进入测试设计 |
| 75-89 | B（良好） | 小幅修订后可用 |
| 60-74 | C（一般） | 需补充完善后使用 |
| 40-59 | D（较差） | 需重大修订 |
| <40 | E（不合格） | 建议重写 |

## 使用示例

```
用户：帮我评估一下这个需求文档的质量
用户：对这份PRD进行测试视角的评分
用户：检查这个需求是否可测试
用户：评估需求文档，如果达标就生成测试用例
```
