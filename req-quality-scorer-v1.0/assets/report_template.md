# 需求文档质量评估报告模板

## 使用说明

本模板定义了需求评估报告的标准输出格式。`scripts/generate_report.py` 基于此模板生成 Word 文档。

---

## 报告结构

### 1. 封面信息

| 字段 | 说明 |
|------|------|
| 文档名称 | 被评估的需求文档名称 |
| 评估时间 | YYYY-MM-DD |
| 综合评分 | XX/100（等级） |
| 评估人 | 签字栏 |

### 2. 维度评分表

| 列 | 说明 |
|----|------|
| 维度 | 六维：可测试性、完整性、清晰性、一致性、可追溯性、可实现性 |
| 得分 | 1-5分 |
| 权重 | 30%/25%/20%/10%/10%/5% |
| 加权分 | 得分×权重 |
| 说明 | 扣分原因简述 |

### 3. 问题清单（分三级）

#### 🔴 阻塞问题
表格列：序号 | 维度 | 问题描述 | 详细问题 | 建议

#### 🟡 警告问题
表格列：序号 | 维度 | 问题描述 | 详细问题 | 建议

#### 🔵 建议问题
表格列：序号 | 维度 | 问题描述 | 详细问题 | 建议

### 4. 改进建议（分三级优先级）

- P0：必须立即补充（阻塞测试设计）
- P1：应尽快补充（影响测试覆盖率）
- P2：建议优化

### 5. 评估等级说明

| 分数段 | 等级 | 说明 |
|--------|------|------|
| 90-100 | A | 可直接进入测试设计 |
| 75-89 | B | 小幅修订后可用 |
| 60-74 | C | 需补充完善后使用 |
| 40-59 | D | 需重大修订 |
| <40 | E | 建议重写 |

### 6. 评估结论

一段总结性文字 + 签字栏

---

## 与测试用例生成联动

评估完成后，若综合评分 >= 60 分（C级及以上），可联动 `generate-test-cases` skill 生成测试用例。

### 联动流程

```
需求文档 → [req-quality-scorer 评估] → 评分报告
                                        ↓
                              评分 >= 60? ──→ [generate-test-cases] → 测试用例Excel
                                  ↓
                              评分 < 60? ──→ 提示先补充P0问题
```

### 联动判断规则

| 评分等级 | 建议动作 |
|----------|----------|
| A/B (>=75) | 直接进入测试用例生成 |
| C (60-74) | 建议先修复警告问题，可同步生成测试用例 |
| D/E (<60) | 必须先补充P0阻塞问题，不建议生成测试用例 |

### 对接 generate-test-cases

当评分达标时，提供以下信息给 `generate-test-cases`：

1. **需求文档路径**：原始 .docx 文件
2. **评估摘要**：各维度得分 + 问题清单
3. **重点关注项**：评估中发现的边界条件、异常场景缺陷，作为测试用例生成的补充提示

使用命令：
```bash
python <generate-test-cases-path>/scripts/generate_cases.py \
  --requirements_file "<需求文档.docx>" \
  --output_file "<输出路径/测试用例.xlsx>"
```
