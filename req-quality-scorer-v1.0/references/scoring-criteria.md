# 评分标准详解

## 一、可测试性（权重 30%）

**核心问题**：测试人员能否根据需求编写测试用例？

### 5分标准
- 每个功能点都有明确的验收标准
- 验收标准可量化、可验证
- 输入输出边界清晰定义
- 业务规则有明确的真假判断条件

### 4分标准
- 大部分功能有验收标准
- 个别边界条件不够明确
- 基本可进行测试设计

### 3分标准
- 验收标准模糊（如"界面友好"、"响应快速"）
- 部分功能缺少验收标准
- 需要测试人员自行推断测试条件

### 2分标准
- 验收标准缺失超过 50%
- 大量使用主观描述
- 测试设计困难

### 1分标准
- 几乎没有验收标准
- 需求描述无法转化为测试用例

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 输入范围 | 是否明确输入的数据类型、范围、格式？ |
| 输出定义 | 是否明确输出的结果形式和内容？ |
| 成功条件 | 成功场景的判断标准是否明确？ |
| 失败条件 | 失败场景的判断标准是否明确？ |
| 性能指标 | 是否有量化的性能要求？ |

---

## 二、完整性（权重 25%）

**核心问题**：是否覆盖了所有必要的测试场景？

### 5分标准
- 覆盖正常流程
- 覆盖异常流程（错误输入、异常状态）
- 覆盖边界条件（最大值、最小值、空值）
- 明确前置条件
- 明确后置条件

### 4分标准
- 正常流程完整
- 异常流程基本覆盖
- 少量边界条件缺失

### 3分标准
- 正常流程完整
- 异常流程不完整
- 边界条件定义不足

### 2分标准
- 只有正常流程
- 异常处理严重缺失
- 无边界条件说明

### 1分标准
- 功能描述不完整
- 关键场景缺失

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 前置条件 | 操作前需要满足什么条件？ |
| 正常流程 | 主流程是否完整？ |
| 异常流程 | 错误场景是否覆盖？ |
| 边界值 | 最大/最小/空值是否说明？ |
| 数据状态 | 不同数据状态下的行为？ |
| 并发场景 | 是否有并发处理说明？ |

---

## 三、清晰性（权重 20%）

**核心问题**：需求是否易于理解且无歧义？

### 5分标准
- 术语统一且有定义
- 句式简洁明确
- 无歧义表述
- 使用用户视角描述

### 4分标准
- 基本清晰
- 个别表述可优化
- 无严重歧义

### 3分标准
- 存在多处模糊表述
- 术语使用不统一
- 部分句子理解困难

### 2分标准
- 大量模糊表述
- 多处歧义
- 需反复确认才能理解

### 1分标准
- 几乎无法理解
- 存在严重歧义

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 术语定义 | 专业术语是否有解释？ |
| 避免模糊词 | 是否避免"等"、"可能"、"大约"？ |
| 主动语态 | 是否使用主动语态？ |
| 单一含义 | 每句话是否只有一个含义？ |
| 图示说明 | 复杂流程是否有配图？ |

---

## 四、一致性（权重 10%）

**核心问题**：需求之间是否存在矛盾？

### 5分标准
- 需求间无矛盾
- 术语使用一致
- 数据模型一致

### 4分标准
- 基本一致
- 存在轻微表述差异（但含义相同）

### 3分标准
- 存在需澄清的表述差异
- 术语使用偶有不一

### 2分标准
- 存在明确矛盾
- 影响测试判断

### 1分标准
- 大量矛盾
- 无法确定正确逻辑

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 逻辑矛盾 | 同一流程不同描述是否一致？ |
| 数据矛盾 | 字段定义是否前后一致？ |
| UI矛盾 | 界面元素描述是否一致？ |
| 术语统一 | 同一概念是否用同一术语？ |

---

## 五、可追溯性（权重 10%）

**核心问题**：需求是否有来源可查？

### 5分标准
- 每个需求有唯一编号
- 关联用户故事/史诗
- 关联业务目标
- 变更有版本记录

### 4分标准
- 有需求编号
- 部分关联上游需求

### 3分标准
- 编号不完整
- 缺少来源追溯

### 2分标准
- 无系统编号
- 无法追溯来源

### 1分标准
- 无任何标识

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 唯一标识 | 是否有需求编号？ |
| 来源关联 | 是否关联业务需求？ |
| 变更记录 | 是否有修订历史？ |
| 版本信息 | 是否有版本号？ |

---

## 六、可实现性（权重 5%）

**核心问题**：技术上是否可行？

### 5分标准
- 技术方案明确
- 现有架构支持
- 无技术风险

### 4分标准
- 基本可行
- 可能有小挑战

### 3分标准
- 存在技术疑问
- 需技术评估

### 2分标准
- 技术风险较高
- 可能需要重大调整

### 1分标准
- 技术上不可行

### 检查要点

| 检查项 | 说明 |
|--------|------|
| 技术依赖 | 是否依赖未确定技术？ |
| 性能可行 | 性能要求是否现实？ |
| 集成影响 | 是否影响现有系统？ |
