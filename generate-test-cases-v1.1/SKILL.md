# 生成测试用例

根据需求文档（.docx），自动生成测试用例并输出为 Excel 文件。支持联动 `req-quality-scorer` 的评估摘要，将 P0/P1 问题写入"备注"列。

---

## 一、目录结构

```
generate-test-cases/              ← 整个文件夹即为 skill，可直接拷贝分发
├── SKILL.md                     # 本文件（必读）
├── scripts/
│   ├── generate_cases.py        # 核心生成脚本
│   └── diag_numbering.py        # 文档编号诊断工具
├── input/                       # 需求文档输入目录（脚本自动创建）
└── output/                      # 测试用例输出目录（脚本自动创建）
```

> 依赖和备用模型配置在 skills 同级目录下：`../requirements.txt`、`../llm-config/llm_config.ini`

| `~/.openclaw/skills/generate-test-cases/` | 副本目录 |

## 三、输出文件命名规则

### 3.1 项目名提取规则

从需求文档文件名中提取项目名，按顺序去掉以下内容：

```
1. 版本号（如 -4.7, -v1.0, -V2.0 等）
2. 文档类型后缀：需求分析说明书 / 需求文档 / 需求规格说明书 / PRD / Product Requirements Document
```

| 输入文件名 | 提取项目名 |
|-----------|-----------|
| `xxx需求分析说明书-4.7.docx` | `xxx` |
| `xxx需求分析说明书.docx` | `xxx` |
| `xxx需求文档.docx` | `xxx` |
| `xxxPRD.docx` | `xxx` |
| `产品需求规格说明书-v1.0.docx` | `产品` |

### 3.2 输出文件名格式

```
{项目名}功能测试用例_{日期-序号}.xlsx
```

- **日期-序号**：格式 `YYYYMMDD-N`，序号从 1 开始，同一天多次运行递增
  - 示例：`xxx项目功能测试用例_20260414-1.xlsx`
- **禁止覆盖**：若文件已存在，脚本自动追加序号

### 3.3 输出目录

**输出到 `D:\test-output\{项目名}\output\` 目录**（脚本自动创建）：

```
D:\test-output\{项目名}\output\
└── <项目名>功能测试用例_<YYYYMMDD-N>.xlsx
```

## 四、执行命令

### 4.1 基本命令（无评估摘要）

```bash
python scripts/generate_cases.py --project "xxx项目"
```

> 脚本使用项目名拼接输入输出路径：`D:\test-input\{项目名}\input\` 和 `D:\test-output\{项目名}\output\`

### 4.2 指定需求文档

```bash
python scripts/generate_cases.py \
  --project "xxx项目" \
  --requirements_file "D:\test-input\xxx项目\input\xxx需求文档.docx"
```

### 4.3 联动评估报告（推荐方式）

```bash
python scripts/generate_cases.py \
  --project "xxx项目" \
  --requirements_file "D:\test-input\xxx项目\input\xxx需求文档.docx" \
  --summary "D:\test-output\xxx项目\analysis_report\xxx评估摘要_20260414-1.json"
```

### 4.4 强制生成（D/E 级评估仍要生成用例）

```bash
python scripts/generate_cases.py \
  --project "xxx项目" \
  --requirements_file "D:\test-input\xxx项目\input\xxx需求文档.docx" \
  --summary "D:\test-output\xxx项目\analysis_report\xxx评估摘要_20260414-1.json" \
  --force
```

## 五、参数说明

> ⚠️ **均为可选参数**：脚本内置自动查找逻辑。

| 参数 | 必填 | 说明 |
|------|------|------|
| `--project` | ❌ | 项目名称（如 `xxx项目`），用于确定输入输出路径 |
| `--requirements_file` | ❌ | 需求文档 .docx 路径；不传则自动从 `input/` 取最新 .docx |
| `--output_file` | ❌ | 输出 .xlsx 路径；不传则自动写入 `output/`，文件名基于项目名自动生成 |
| `--summary` | ❌ | 评估摘要 JSON 路径（由 req-quality-scorer 生成）；传入后在"备注"列标注 P0/P1 问题 |
| `--force` | ❌ | 强制生成（即使评估等级为 D/E，仍生成用例但会报警告） |

## 六、模型配置

### 6.1 模型选择策略（优先级）

```
① OpenClaw 本地模型（http://127.0.0.1:19000/proxy/llm，模型ID: modelroute）
   └─ 零配置，优先使用；端口通（405）即视为在线
② 其他 LLM API（llm-config/llm_config.ini 中 api_key + base_url）
   └─ 仅在①不可用时触发
③ 报错退出（无任何可用模型）
```

### 6.2 llm_config.ini 当前格式

```ini
[llm]
api_key = your_api_key_here
base_url = https://api.example.com/v1
model = your-model-name
```

> ⚠️ **key 不能直接拷贝**：llm_config.ini 含个人 API Key，分发前需替换为 `your_api_key_here` 占位符。

### 6.3 不同模型产出差异

| 模型 | 每模块用例数 | 稳定性 | 说明 |
|------|------------|--------|------|
| OpenClaw 本地模型（modelroute） | 15~36条 | 中 | 随机性较大，可通过 `--summary` 辅助约束 |
| 其他 LLM API | 10~20条 | 高 | 产出偏少，建议优先用本地模型 |

> **经验**：同模型不同次跑，单模块用例数波动 ±30% 是正常现象，与 AI 随机性相关。

## 七、与 req-quality-scorer 联动

### 联动时机

| 评估等级 | p0_count | 动作 |
|----------|----------|------|
| A / B | - | ✅ 直接生成 |
| C | = 0 | ⚠️ 提示用户后可生成 |
| C | > 0 | 🔴 先修复 P0 |
| D / E | - | 🔴 先修复 P0；用户坚持则 `--force` |

### 联动步骤

1. 读取 `req-quality-scorer/analysis_report/` 中的 `*评估摘要_YYYYMMDD-N.json`
2. 检查 `level` 和 `p0_count` 字段
3. 执行命令（传 `--summary`）
4. 脚本将 P0/P1 问题自动写入"备注"列

### 评估摘要 JSON 关键字段

```json
{
  "level": "D（较差）",
  "p0_count": 2,
  "p1_count": 5,
  "p2_count": 2,
  "problems": [
    {
      "severity": "🔴 P0",
      "dimension": "完整性",
      "title": "异常场景缺失",
      "detail": "...",
      "suggest": "补充接口异常处理流程..."
    }
  ]
}
```

## 八、输出测试用例结构

### 8.1 列结构（9列，当前格式）

| 列 | 字段 | 说明 |
|----|------|------|
| A | 需求编号 | 功能点编码，如 `F_UC_A_YHGL_YHLB_W1`，从需求文档括号中提取 |
| B | 用例编号 | `CS-{前缀}-{序号}`，每模块内从 001 重新编号 |
| C | 用例等级 | P0 / P1 / P2 / P3 |
| D | 用例标题 | **模块行**=完整模块路径（含章节号与编码，用 `-` 分隔）；**用例行**=用例名称 |
| E | 预置条件 | 测试前需满足的条件（自动去旧编号，换行） |
| F | 操作步骤 | 详细操作步骤（自动去旧编号，加 `1. 2. 3. ` 序号，换行） |
| G | 预期结果 | 预期输出（自动去旧编号，加 `1. 2. 3. ` 序号，换行） |
| H | 执行结果 | 默认空，测试执行后填写（通过/失败/阻塞） |
| I | 备注 | ⚠️ 传入 `--summary` 后，P0/P1 问题及改进建议自动写入此列 |

> ⚠️ **重要**：本 skill 经历过一次重大格式升级（v1→v2），9列格式为当前标准，
> `需求编号` 列是 v2 新增的，用例编号前缀与需求编号中编码对应。
> 若旧版用例是8列格式，用 Excel/VBA 将第一列重命名为"需求编号"即可对齐。

### 8.2 用例编号规则

```
格式：CS-{前缀}-{序号3位}
规则：每个模块独立编号，模块切换时从 001 重新开始

示例：
  模块：用户管理 > 查看用户列表（F_UC_A_YHGL_YHLB）
    → CS-YHLB-001 ~ CS-YHLB-017
  模块：用户管理 > 查看用户详情（F_UC_A_YHGL_YHXQ）
    → CS-YHXQ-001 ~ CS-YHXQ-010
  模块：订单管理 > 创建订单（F_UC_A_DDGL_CJDD）
    → CS-CJDD-001 ~ CS-CJDD-010
```

**前缀提取算法（`_extract_module_prefix()`）：**

```
输入示例：模块路径
  订单管理 > 创建订单 > 填写订单信息（F_UC_A_DDGL_CJDD）

处理步骤：
  1. 从路径中提取所有括号内编码（支持中文括号（）和英文括号()）
  2. 取最后一个编码（最细粒度子级）→ F_UC_A_DDGL_CJDD
  3. 去掉前导框架前缀（F_UC_B_）→ DDGL_CJDD
  4. 提取 W\d 后缀（如有）→ W1 等
  5. 去掉 W\d 后缀，取末段拼音 → CJDD
  6. 防重检查：若前缀已使用，追加 W\d 后缀区分

防重规则（关键）：
  如果末级子模块拼音相同，则追加 W\d 后缀确保编号唯一。

示例：
  F_UC_A_DDGL_SQ_W1（PC申请）→ 基础前缀 SQ → 首次使用 → SQ
  F_UC_A_DDGL_SQ_W2（移动申请）→ 基础前缀 SQ → 已重复 → 追加W2 → SQW2
  F_UC_A_DDGL_SQ_W3（其他申请）→ 基础前缀 SQ → 已重复 → 追加W3 → SQW3

  结果：
    PC申请模块：CS-SQ-001 ~ CS-SQ-010
    移动申请模块：CS-SQW2-001 ~ CS-SQW2-008
    其他申请模块：CS-SQW3-001 ~ CS-SQW3-005
```

**编号重置规则：**

| 场景 | 编号行为 |
|------|---------|
| 同一模块内 | 连续递增（001→002→003...） |
| 模块切换时 | 重置为 001，前缀更新为新模块的子级拼音 |
| 全局 | 不保证唯一（允许不同模块出现相同序号，如 CS-SJLB-001 和 CS-SJXQ-001） |

### 8.2.1 模块行显示规则

```
格式：父级模块 - 当前模块（编码）
示例：
  4.3 用户管理功能（UC_A_YHGL）描述 - 4.3.2.1. 用户列表功能

规则：
  - 完整层级路径，用 `-` 连接各层级标题（v2 起从 `>` 改为 `-`）
  - 最末级保留括号内的功能点编码
  - 不对 `-` 符号做XML转义（Excel单元格直接支持）
```

### 8.3 操作步骤 & 预期结果编号逻辑

LLM 返回的步骤/预期结果可能含旧编号（如 `"1. xxx"`），或为单行分号分隔文本。
脚本自动处理后统一输出为 `1. 2. 3. ` 格式，换行显示。

**处理策略（`scripts/generate_cases.py` 中的内联逻辑）：**

```
操作步骤：
  0. 先把字面量 \\n 替换为真正的换行符 \n
  1. 取 steps[] 列表每项
  2. 去旧编号（r'^\d+[.)、\s]+' + r'^\d+[)）]\s*'）
  3. 重新加 1. 2. 3. 前缀，\n 换行

前置条件：
  0. 先把字面量 \\n 替换为真正的换行符 \n
  1. 按 \n / ; / ； 分割原始文本
  2. 每段去旧编号（同上正则）
  3. 重新加 1. 2. 3. 前缀，\n 换行

预期结果：
  0. 先把字面量 \\n（反斜杠+n两个字符）替换为真正的换行符 \n
  1. 按 \n / ; / ； 分割原始文本
  2. 每段去旧编号（同上正则）
  3. 重新加 1. 2. 3. 前缀，\n 换行

示例：
  LLM原始操作步骤：["1. 点击发布按钮", "2. 填写表单内容"]
  处理后：
    1. 点击发布按钮
    2. 填写表单内容

  LLM原始预期结果：1. 左侧显示发布通知列表页面;2. 右侧默认显示空白页
  处理后：
    1. 左侧显示发布通知列表页面
    2. 右侧默认显示空白页
```

### 8.4 视觉效果

| 位置 | 底色 | 自动换行 | 字体 |
|------|------|---------|------|
| 表头行 | 深蓝 #4472C4 | ✅ 开启 | 白字粗体 |
| 模块行 | 浅蓝 #DCE6F1 | ❌ 关闭（标题不自动换行） | 深蓝粗体 |
| 用例行 | 无（透明 #000000） | ✅ 开启 | 正常 |
| 用例编号 | 无（透明） | ✅ 开启 | 正常 |
| 备注列 | 无 | ✅ 开启 | 正常 |

**重要：**
- 模块行 `wrap_text=False`：避免标题超长时 Excel 自动折行导致行高异常

- 用例编号在 A 列水平居中，其他列左对齐

## 九、模块名提取规则

### 9.1 完整层级路径

模块名采用**完整层级路径**展示，用 `>` 连接各层级标题：

```
格式：父级模块 > 当前模块（编码）

示例：
  4.3 用户管理功能模块（F_UC_A_YHGL） > 4.3.2.1 用户列表功能点(F_UC_A_YHGL_YHLB)
  订单管理 > 创建订单 > 填写订单信息（F_UC_A_DDGL_CJDD）
```

**规则：**
- 从文档标题层级中提取所有有效模块标题
- 用 `>` 连接，保留章节号与功能点编码
- 最末级保留括号内的功能点编码

### 9.2 段落标题过滤（黑名单）

文档中的**段落标题**（如"功能点划分"、"业务处理流程及业务逻辑"）不属于模块层级，应被过滤掉。

**过滤关键词列表（`_is_content_section()` 函数）：**

```python
KEYWORDS = [
    '处理流程', '业务逻辑', '业务规则',
    '原型界面', '界面说明', '界面设计', '界面原型',
    '数据要求', '数据字典', '非功能需求', '数据结构',
    '接口说明', '接口设计',
    '流程说明', '流程描述',
    '状态说明', '状态转换', '状态机',
    '备注说明', '补充说明', '其他说明',
    '约束条件', '前提条件', '异常处理',
    '性能要求', '安全要求',
    '功能点划分', '功能描述', '功能说明', '功能概述',
    '需求描述', '总体描述', '概述', '总则',
    '功能需求模型', '项目功能需求',
]
```

**过滤逻辑：**

```
对每个标题文本：
  1. 检查是否包含上述关键词
  2. 若包含 → 过滤掉（不计入模块层级）
  3. 若不含 → 保留为有效模块标题
```

**示例：**

```
文档标题层级：
  L1: 4 项目功能需求模型描述          → FILTERED by [功能需求模型]
  L2: 4.3 用户管理功能模块（F_UC_A_YHGL）  → KEPT
  L3: 4.3.2 功能点划分                 → FILTERED by [功能点划分]
  L4: 4.3.2.1 用户列表功能点(F_UC_A_YHGL_YHLB)  → KEPT
  L5: 业务处理流程及业务逻辑           → FILTERED by [业务处理]

最终模块名：
  4.3 用户管理功能模块（F_UC_A_YHGL） > 4.3.2.1 用户列表功能点(F_UC_A_YHGL_YHLB)
```

### 9.3 实现位置

- 函数：`scripts/generate_cases.py` 中的 `extract_content_with_titles()`
- 过滤函数：`_is_content_section(title_text)`

## 十、常见问题

### 🔴 P0 级问题（会导致用例缺失或格式错误）

---

**Q: 用例数量比预期少很多？**
A: 排查方向按优先级：
1. **模型差异**：不同 LLM 每模块产出量不同；本地模型 15~36 条。确认当前用的是哪个模型。
2. **英文过滤跳过**：日志中搜 `WARNING.*英文`，被跳过的模块用例为 0。
3. **文档格式异常**：检查 `_is_content_section()` 黑名单关键词是否误杀了有效模块。
4. **文档重复功能点**：同一条功能编码在文档中出现多次，去重后只保留第一条。

---

**Q: 某些模块完全没有用例？**
A: 通常是**英文过滤**导致。日志中会看到：
```
WARNING: 跳过含英文内容的功能点: xxx（英文比例: 0.XX）
```
**原因**：LLM 返回的 JSON 含英文思考过程，脚本检测到英文比例超过阈值则跳过该模块。
**处理**：
- 删除 output/ 中已生成的旧文件，重跑（AI 随机性可能第二次通过过滤）
- 若频繁跳过，考虑降低 `ENGLISH_RATIO_THRESHOLD` 阈值（当前默认 0.3）

---

**Q: 用例编号重复？**
A: 根因在**文档本身**：同一个功能点编码重复出现多次。
`extracted_modules` 已加去重逻辑，基于 `module_name` 去重保留首次出现。
若仍重复，检查文档是否有多个章节描述同一功能点。

---

### 🟡 P1 级问题（格式/体验问题）

---

**Q: 生成的 Excel 列宽不合适？**
A: 自适应列宽逻辑已更新为**排除模块行，仅用数据行计算**：
```python
if r[1] and str(r[1]).startswith('CS-'):
    data_rows.append(row)
```
模块标题行本身不参与列宽计算，避免行标题超长时强制撑开整列。

---

**Q: 模块行显示用 `>` 分隔还是 `-`？**
A: **当前标准是 `-`**。若发现 Excel 中仍显示 `>`，说明脚本版本未同步。

---

**Q: 预期结果/操作步骤中的旧编号没被去掉？**
A: 脚本处理逻辑：
1. 把字面量 `\n` 替换为真正换行符
2. 按 `\n` / `;` / `；` 分割文本
3. 去掉每段头部的 `数字+标点` 前缀
4. 重新加 `1. 2. 3. ` 前缀

---

**Q: 备注文本太长？**
A: 正常现象——传入 `--summary` 后，所有 P0/P1 问题及改进建议都会写入备注列。
测试人员执行用例前需与需求方逐项确认。无法精简。

### 🟢 配置与部署

---

**Q: 本地模型不可用，报错 "OpenClaw 本地模型不可用"？**
A: 排查步骤：
1. 确认 OpenClaw Gateway 在运行：`openclaw gateway status`
2. 测试端口连通：`curl http://127.0.0.1:19000/proxy/llm/chat/completions`（405=通，404=路径错）
3. 检查 `llm-config/llm_config.ini` 是否配置了有效的 API Key
4. 若均无，填入有效的 API Key

---

**Q: 如何在不同电脑/智能体间迁移？**
A: 拷贝整个 `generate-test-cases/` 文件夹即可，目标机器只需确保 Python 依赖已安装。

---

**Q: 执行结果列和备注列的顺序是什么？**
A: 当前顺序（从左到右）：
需求编号 → 用例编号 → 用例等级 → 用例标题 → 预置条件 → 操作步骤 → 预期结果 → **执行结果** → **备注**
即第8列（H列）= 执行结果，第9列（I列）= 备注。
