# Excel 测试用例标准模板

> 本文档定义生成的 Excel 文件（`{项目名}接口测试用例及测试结果_YYYYMMDD_HHMMSS.xlsx`）的结构、列定义和样式规范。生成 Excel 时引用本文件。

---

## 一、文件结构

生成的 Excel 文件包含 **2 个 Sheet**：

| Sheet 名称 | 内容 | 用例编号规则 |
|-----------|------|-------------|
| 单接口 | 所有单接口测试用例 | TC001 起 |
| 业务流程 | 所有业务流程测试用例 | FC001 起，每条流程独立编号，步骤用 FC001-Step1/2/3... 表示 |

```
{项目名}接口测试用例及测试结果_YYYYMMDD_HHMMSS.xlsx
├── Sheet "单接口"    ← 单接口测试用例，TC001~TC999
└── Sheet "业务流程"  ← 业务流程测试用例，FC001-Step1/2...
```

> 命名中"**及测试结果**"后缀表明本文件不仅是设计阶段的用例清单，还同时承载执行后的实际 HTTP 状态、PASS/FAIL 结果 —— 一份文件覆盖用例与结果两个维度。

---

## 二、列定义（10 列，固定顺序）

| # | 列名 | 列宽 | 说明 |
|---|------|------|------|
| 1 | 用例编号 | 12 | 单接口：TC001~TC999；业务流程：FC001-Step1/2/3... |
| 2 | 接口名称 | 28 | 中文接口名（与 Apifox summary 对齐）；业务流程填流程名 |
| 3 | 请求方式 | 10 | GET / POST / PUT / DELETE |
| 4 | 请求路径 | 42 | 完整路径，含 `{uuid}` 等 path 参数占位符 |
| 5 | 测试类型 | 14 | 单接口：正向 / 逆向 / 边界 / 安全；业务流程：业务流程 |
| 6 | 测试描述 | 40 | 一句话描述测试场景 |
| 7 | 请求参数 | 55 | Query: `key=value`；Body: 关键字段 JSON 片段；Path: 标注路径参数；多余通用字段可省略 |
| 8 | 预期结果 | 45 | 完整预期描述，如 `HTTP 200，接口成功`、`HTTP 500，缺少必填字段`（详见 [case-design.md](../case-design.md) 3.4 撰写规范） |
| 9 | 实际结果 | 35 | 实际 HTTP 状态码及实际响应描述（如 `200，成功` 或 `500，缺少必填字段`） |
| 10 | 执行结果 | 12 | PASS（绿底）/ FAIL（红底） |

---

## 三、样式规范

- **表头**：背景色 `#4472C4` 深蓝、白色加粗、字体微软雅黑 11pt、行高 28pt、水平垂直居中。
- **数据行**：字体微软雅黑 10pt、行高 36pt、左对齐（编号/方式/类型/状态/结果列居中）。
- **执行结果着色**：
  - PASS → 字体 `#006100` 加粗，背景 `#E2EFDA`
  - FAIL → 字体 `#9C0006` 加粗，背景 `#FFC7CE`
- **业务流程父行**：背景 `#D9E1F2`（浅蓝），字体 `#1F3864` 深蓝加粗，合并 A~J 列
- **冻结**：`A2`，首行始终可见。
- **边框**：所有单元格细边框 `#BFBFBF`。

---

## 四、业务流程用例在 Excel 中的呈现

| 用例编号 | 接口名称 | 测试类型 | 测试描述 |
|---------|---------|---------|---------|

| FC001 | 查询订单 | 业务流程 | Step3: 查询订单详情 |
| FC001 | 取消订单 | 业务流程 | Step4: 取消订单（cleanup） |
| FC002 | 用户登录 | 业务流程 | Step1: 用户登录 |
| FC002 | 创建订单 | 业务流程 | Step2: 创建订单并发起审批 |
| ... | ... | ... | ... |
