# Word 测试报告标准模板

> 本文档定义生成的 Word 测试报告（`{项目名}接口测试报告_YYYYMMDD_HHMMSS.docx`）的章节结构、表格格式、问题分类规则和样式规范。生成 Word 报告时引用本文件。

---

## 一、报告章节结构

测试报告必须包含以下 **6 个章节**，按顺序排列：

| 章节 | 内容 | 必须 |
|------|------|------|
| 一、测试概要 | 2 列 key-value 表：测试时间、服务地址、接口总数、业务流程数、用例总数、通过/失败数量、通过率、测试类型 | ✅ |
| 二、接口用例统计 | 5 列：接口/流程名称、请求路径、用例数、通过、失败 —— 单接口和业务流程**合并在同一张表**，业务流程行的"请求路径"写 `(多接口串联)` | ✅ |
| 三、失败用例及问题分析 | 每个接口/流程一个 `Heading 2` 小节（3.1 ~ 3.N），下挂 5 列失败用例表；无失败的小节写"本接口无失败用例。" | ✅ |
| 四、修复建议 | 按接口/流程分组，`【接口名】` 段落 + `List Bullet` 条目，按问题类别聚合："参数校验缺失（N条）"形式 | ✅ |
| 五、测试覆盖说明 | 2 列表：测试类型 / 说明，必须列出**正向、逆向、边界、安全、业务流程测试** 5 类 | ✅ |
| 六、附录 | 测试用例分布（按接口 bullet 列出每接口用例数及各类型拆分） + "总计 N 条" + 对应 Excel 文件名引用 | ✅ |

---

## 二、测试概要表格格式

| 配置项 | 值 |
|--------|-----|
| 测试时间 | YYYY-MM-DD HH:MM:SS |
| 服务地址 | http://xxx.xxx.xxx/项目名 |
| 接口总数 | N 个 |
| 业务流程数 | N 条 |
| 用例总数 | N 条 |
| 通过数量 | N 条 |
| 失败数量 | N 条 |
| 通过率 | XX.X% |
| 测试类型 | 正向测试、逆向测试、边界测试、安全测试、业务流程测试 |

---

## 三、失败用例表格格式

每个接口/流程独立的 5 列表格：

| 用例编号 | 测试描述 | 预期结果 | 实际结果 | 问题分析 |
|---------|---------|---------|---------|----------|
| TC011 | 缺少registrationTime字段 | HTTP 500，参数错误 | HTTP 200，接口成功 | 未校验必填字段 |
| TC074 | Step2: 分页列表应能查到刚创建的草稿 | HTTP 200，records 包含新草稿 | HTTP 200，接口成功 | 业务校验缺失 |

### 3.1 问题分析填写规则

实现见生成脚本中的 `classify_failure` 函数：

- 期望 401 / Token / mobile 相关失败但实际成功 → `鉴权校验缺失`
- 期望参数错误（必填缺失、为空、超长、格式错误）但成功 → `参数校验缺失`
- 期望格式报错但实际成功 → `缺少参数格式校验`
- 期望"数据不存在"但实际成功 → `未校验数据存在性`
- SQL / XSS 注入未拦截 → `安全校验待加强`
- 期望业务规则拦截（如审批中不可删除）但实际成功 → `业务规则校验缺失`
- 网络请求失败 → `网络问题`
- 其他 → `业务校验缺失`

### 3.2 失败分类定义

| 分类 | 判定条件 |
|------|---------|
| 内部异常/数据不存在 | HTTP 200 但 response 中 message 含"内部异常"或"数据不存在" |
| 格式/模式不支持 | 响应体中 message 含"格式不支持"或"金山文档格式"相关 |
| 数据/参数问题 | 响应为空 / data 为 null / 响应缺少关键字段 |
| 网络问题 | 请求超时 / 连接被拒绝 / DNS 解析失败 |
| 其他 | 不属于以上所有分类的失败 |

## 四、修复建议格式

按接口分组，每条以 `•` 开头，按问题类别聚合计数：

```
【用户登录】
  • 参数校验缺失（3条用例）

【创建订单】
  • 参数校验缺失（2条用例）

【业务流程-用户登录→创建订单→查询→取消】
  • 业务校验缺失（1条用例）
  • 参数校验缺失（1条用例）
```

## 五、测试覆盖说明格式

| 测试类型 | 说明 |
|---------|------|
| 正向测试 | 验证正常业务流程，包括完整合法数据、默认参数、不同组合 |
| 逆向测试 | 验证异常场景处理，包括必填字段缺失、字段为空、不存在的 uuid/fileId、非法参数值等 |
| 边界测试 | 验证边界值处理，包括最小/最大长度、超长字符、空字符串、特殊字符、超大分页、非法日期格式等 |
| 安全测试 | 验证安全性，包括 SQL 注入、XSS 脚本攻击等 |
| 业务流程测试 | 验证跨接口端到端流程，覆盖完整业务链路（如创建→查询→编辑→删除），确保接口间数据传递正确 |

## 六、样式规范

- **标题** 用 `Title` 样式，**章节** 用 `Heading 1`，**小节** 用 `Heading 2`。
- **所有表格** 使用 `Table Grid` 样式。
- **表头** 背景 `#4472C4`、白字加粗、居中、微软雅黑 10.5pt。
- **数据行** 微软雅黑 10pt；短内容（数字、编号）居中，长文本左对齐。
- **Bullet 列表** 使用 `List Bullet` 样式。

---

## 七、报告命名规范

```
{项目名}接口测试报告_YYYYMMDD_HHMMSS.docx
```

时间戳必须与同一次测试生成的 Excel 和 JSON **完全一致**。
